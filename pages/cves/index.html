GHSA-773r-585g-6vc3 In Progress

Per-Account Login Rate Limit Bypass via Username Case Variation

Rate Limit Bypass Authentication

The login rate limit is applied per username exactly as provided. By changing the case of the username (e.g., "User" vs "user"), an attacker can bypass the per-account lockout mechanism and perform unlimited brute-force attempts. Published Nov 4, 2026.

CVE-2026-121735 Disclosed

Account Confirmation Tokens Have No Expiry Window

CWE-613 Token Expiry

When someone registers, a confirmation token is generated and emailed to them. The code only verifies that the token matches and the account isn't already confirmed, but never checks how old the token is. The token stays valid forever, allowing anyone with an old confirmation email to activate an account that was never meant to be active.

Account Email Enumeration and Improper Rate-Limit Enforcement in Password Reset

Enumeration Password Reset

The password reset endpoint returns different responses for valid vs. invalid email addresses, allowing attackers to enumerate registered users. Additionally, the rate limit can be bypassed by distributing requests. Published Nov 4, 2026.
